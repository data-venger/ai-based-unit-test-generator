# AI-Based Unit Test Generator

This project automatically generates **unit test cases** for Python code using LLM-powered prompts and configurable rules.  
It scans source files in a given directory, generates `pytest` tests, and saves them into a dedicated `tests/` folder.  

The goal is to **improve testing efficiency, coverage, and code quality** with minimal manual effort.

---

## 🚀 Features
- Auto-generates **high-quality pytest unit tests**
- Customizable with YAML-based configuration
- Supports **path inclusion/exclusion** for code scanning
- Extensible for new runners, reporting formats, or frameworks
- Lightweight: built on **Python + Pytest + YAML**

## 🛠️ Installation & Setup

### Prerequisites
- Python **3.x**  
- Dependencies: `pytest`, `pytest-cov`, `pyyaml`, `lxml`

### Clone & Install
```bash
git clone https://github.com/data-venger/ai-based-unit-test-generator.git
cd ai-based-unit-test-generator
pip install -r requirements.txt
```

### ⚙️ Configurable Options

Model: LLM model name (local Ollama or API-backed)

Endpoint: API endpoint for generation

Paths: Include/exclude specific source folders

File Patterns: Define file extensions to scan (e.g., .py)

Prompt: Customize generation rules & style

Output: Default location is tests/


## ⚠️ Notes & Limitations

- Since the test cases are generated by an **AI model**, you may need to apply **minor manual fixes** to the generated test files.  
- You can also **tune the prompt** in the config file to get better and more tailored test cases.  
- Generated tests are meant as a **starting point**, not a full replacement for human validation.  

### Handling Heavy Imports (Airflow, PySpark, etc.)
- Some libraries (e.g., **Apache Airflow**, **PySpark**, **TensorFlow**) are very heavy and not always required for unit test generation.  
- The generator handles this by:
  - **Stubbing / mocking imports** where possible (so tests don’t need the full framework installed).  
  - Allowing you to **exclude certain modules** via the `exclude_paths` or config prompt tuning.  
  - Recommending lightweight **mocking with `monkeypatch`** for external services.  

👉 Example: Instead of requiring a full Airflow DAG environment, generated tests can mock just the operator or function under test.  

This approach ensures tests run **fast and reliably**, even without installing heavy dependencies locally.

## 🧩 Extending the Project

You can extend this project in multiple ways:

- **Runners (`runners/`)**  
  Add new execution backends for different AI models or APIs.

- **Reporting (`reporting/`)**  
  Customize or extend coverage and summary reports.

- **Frameworks**  
  Add support for testing frameworks beyond `pytest` (e.g., `unittest`, `nose`).

- **Languages**  
  Extend scanning logic to support languages beyond Python by customizing `file_globs` and generation prompts.

- **Templates**  
  Modify test file generation style by updating the prompt preamble.

- **Handling Heavy Imports**  
  Enhance support for complex ecosystems like **Airflow** or **PySpark** by:  
  - Improving mocking/stubbing strategies for large dependencies  
  - Creating plugin-like adapters for common frameworks  
  - Providing pre-built config snippets for specific frameworks  

This makes it easier to generate lightweight tests for projects using **enterprise-scale frameworks** without requiring full installations locally.
